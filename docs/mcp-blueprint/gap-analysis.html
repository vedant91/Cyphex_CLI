CYPHEX MCP · GAP ANALYSIS · AFTER THE FIRST REAL TEST ON AN OUTSIDE PROJECT

Where Cyphex MCP stands, and what makes it credible

An outside Claude session used the MCP on a real project (a backend and a frontend repo) and scored it about 4 out of 10. I checked each of its claims against the files that session left on disk. Most were right. Here is what is true, what I fixed in this pass, what is still open, and how other tools compare.

The short answerThe MCP is good at keeping an agent honest and poor at finding bugs by itself. It has no analyzer of its own, and it takes the agent's word on whether an attack worked or a fix held. Credibility comes from turning every "the agent says" into "Cyphex measured". This pass fixed the parts that were cheap to measure. The big parts, running the scanners and running the proofs, are the next build.

What this meansAnyone with a real engine is either static (Semgrep, Snyk) or dynamic (ZAP, Burp). The autonomous attackers (Strix) combine an agent with a sandbox, which is the closest to Cyphex's goal. Nobody in this list sells a fix that Cyphex itself re-attacked and measured, with a readable audit trail kept on your own machine. That is the opening. It only works if "measured" is true, which today it is not for the attack and the replay.

3Mimicking the Cyphex CLI: what the MCP dropped

The MCP was meant to be the CLI's engine behind an agent. I removed the engine's own analyzers early (a decision made to avoid hosting models) and kept only the orchestration. 5Rules that make it credible

  • Measured beats claimed. Every fact on the report says who produced it. The agent never grades itself.
  • No "fixed" without a before and an after that Cyphex ran. If it cannot run them, the answer is "could not verify", never PASS.
  • Coverage is a number. "Read 8 of 8 files, 19 of 19 routes" or "4% read". Never a vague "reviewed".
  • A person decides the risky things (webhook, where tests run, starting containers), and their words are on the record.
  • Treat the scanned code as hostile. It may contain text aimed at the agent. Cyphex only ever reads structured results from it.
  • Publish the misses. A benchmark page that shows what Cyphex failed to find is what makes the hits believable.

6What changed in this pass, and the limits of this analysis

  • Human-in-the-loop gate on start_scan, with recorded answers and a webhook URL, secret and steps when the answer is yes.
  • A local security folder: one folder per run, SECURITY_LOG.md across runs, and a get_history tool.
  • Genome: files returned and listed, one file per repo, thresholds calibrated, honest numbers shown.
  • Verify Gate: PASS requires a proven baseline. Facts are labelled measured or reported.
  • Coverage measured by Cyphex, and a partial route list can no longer be high trust.
  • Report rebuilt. Tests: 9 core, 28 pipeline and 36 end-to-end checks pass.
  • Second pass, the agents. deploy_agents writes 20 Claude Code subagents into the project (route mapper, ten bug-class specialists, prober, four independent reviewers, patcher, two fix reviewers, agent-security auditor), each with its own prompt, tool list, guardrails and optionally its own model. Reviewers each cast one ballot without seeing the others, and the MCP tallies once three are in. A patcher proposes and two reviewers approve separately. Two agents reporting one bug are merged and both credited.
  • Agent evaluation. A scorecard per agent counted from what the MCP recorded: findings reported, confirmed, dismissed, proven, files read, how often a reviewer sided with the majority, how each fix ended.
  • Agent security. audit_agent_config reads a project's agent setup for risky settings (broad shell permission, an agent with every tool, an unpinned tool server, a credential in clear text, a login header over plain http). plant_canary plants an instruction in a scratch copy of the code and checks whether any agent obeys it. Both appear in the report.
  • A genuine limit hit during the live run. The prober agent that writes attack requests was stopped by Anthropic's cyber safeguards. I did not retry, reword or do its work, so the dynamic-testing stage was not run and the report says nothing was proven by attack. Anyone running this on their own should expect that stage to need either their own session or Anthropic's Cyber Verification Program.
