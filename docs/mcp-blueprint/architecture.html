Cyphex MCP, end to end

How the MCP is called, what it does, where the agents run, how the sandbox is hardened, how a finding becomes a verified fix, and how we test the MCP itself. Every status pill says whether it is built and verified, a stub, or still to do.

Cyphex MCP Host agent + user's machine User's edge Testing

01The big picture

Three actors. The coding agent reasons, the user's Docker runs the target, and Cyphex hands out playbooks and runs the gates that must not be opinions.

02How the MCP is called

Two ways to reach the same server. Locally the client launches it as a child process over stdio. In the demo container it listens on HTTP. The tool calls are identical either way.

How you connectCommandUse it for
Local, stdioclaude mcp add cyphex -- cyphex-mcpReal use. It runs on your machine, so it can see your Docker and detect gVisor.
Container, HTTPdocker compose -f cyphex_mcp/docker-compose.demo.yml up --build then connect to http://localhost:8765/mcpTutorial and experiments. No Docker socket inside, so it always recommends the hardened-docker tier.

03How the agents are deployed

"Deploying an agent" here means handing the host model a role sheet. Nothing is installed or hosted. The MCP returns the roles, the host agent plays them in order, and each returns JSON in a fixed shape.

04The sandbox, hardened

The old sandbox gave the target the default network, so a compromised app could phone home. The new recipe removes that route and adds a second tier when the user's Docker supports gVisor.

05Genome and agent security

The scan teaches a behavioural model what normal traffic looks like. That model ships to the user's edge, where it blocks shapes it has never seen, which is how a zero-day with no signature still gets stopped. Agent security rides in the same server as guardrails and one gate tool.

06How it is tested, end to end

Two separate questions. First, does the MCP itself work? Second, does a scan through the MCP find and fix real bugs? The first is built and passing. The second is the next phase.

07From a GitHub push to the report

A webhook can record that code landed, but it cannot scan: the MCP has no model. So a CI runner starts a headless agent, the agent calls the MCP, and the MCP grades every step and writes the report.
