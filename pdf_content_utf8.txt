#01Innovation and CreativityDoes your agent solve a problem in a way that was not obvious? Did you combine tools or domains non-trivially?
QA Fraternity | AI Agent Hackathon | 16 May 2026
What Judges Look For•  Problem selection: is this a real, painful, underserved gap in QA?•  Novelty of the reasoning loop: does it go beyond one LLM call and return?•  Non-obvious combinations: e.g. correlating test failures with deployment eventsWhat Kills This Score•  Wrapping a prompt in a UI and calling it an agent•  Solving a problem 10 SaaS tools already solve•  No agent loop: LLM is called once, result is returned, nothing happens afterHow to Score High•  Pick a problem your team actually suffers from every sprint•  The more specific the pain, the more innovative the solution appears•  Generic tracks produce generic agents: go narrow and deep"We built an agent that detects flaky tests by correlating failure timestamps with CI infrastructure events" scores higher than "We built an agent that generates test cases."

#02Technical ImplementationDoes it actually work? Is the agent architecture sound? Is the loop real or just chained prompts?
QA Fraternity | AI Agent Hackathon | 16 May 2026
What Judges Look For•  Agent reads its own tool output and decides the next step•  Tools are selected dynamically, not hardcoded in sequence•  Agent recovers from failures: retries, heals, escalates, or stops gracefully•  Reasoning steps are visible, not a black box•  At least one live external integration (GitHub, JIRA, Playwright, real URL)What Kills This Score•  Single LLM call with no loop•  Crashes or returns a generic error on first failure•  Everything mocked or local-file only•  Demo is pre-recorded outputHow to Score High•  Show the agent trace live: what it decided and why•  Multi-agent architecture earns bonus points•  Tool use with retry and fallback built into the agent•  Minimum bar: one real external integration, decisions visibleObservable reasoning: the audience can see the agent decide, not just see the final answer.

#03Real-world Impact and UsabilityWould a real QA team actually use this on Monday? Does it solve a problem at the right level of abstraction?
QA Fraternity | AI Agent Hackathon | 16 May 2026
What Judges Look For•  Specificity: 'flaky API tests in our payment service' beats 'test automation in general'•  Quantified value: 'saves 3 hours per sprint' is convincing•  Ease of use: QA engineers who are not AI experts can get value in 10 minutes•  Plugs into real tools: JIRA, GitHub, Slack, or existing CI pipelineWhat Kills This Score•  Only the builder can operate it•  Requires 20 setup steps before first run•  Solving a problem that does not cause real sprint pain•  Too broad: 'an agent that does all QA' is not usableHow to Score High•  Name a specific role, a specific moment, and a specific task eliminated•  Demo to a QA engineer who has never seen it, not to a developer•  One real integration done well beats five integrations that do not workThe one question to answer: Who specifically uses this, in what moment, and what do they stop doing manually?

#04Quality of DemoCan you show your agent working clearly in 5 minutes? Does the panel understand and trust what they saw?
QA Fraternity | AI Agent Hackathon | 16 May 2026
What Judges Look For•  Live agent running with a visible reasoning trace•  Problem stated crisply in under 30 seconds from memory•  Narrating decisions as the agent runs, no silence•  Q&A handled with depth and honestyWhat Kills This Score•  3 minutes on architecture diagrams, 30 seconds on a screenshot•  'It works, trust me': show it•  Reading slides during the demo•  Going silent while the agent runsHow to Score High•  Design the demo scenario before you write a line of code•  Have a 60-second screen recording fallback ready•  Recovering from a live failure out loud earns composure points•  'I do not know but here is how I would find out' beats a wrong confident answerSilence during a running agent means the panel loses trust that it is real. Narrate every decision.
