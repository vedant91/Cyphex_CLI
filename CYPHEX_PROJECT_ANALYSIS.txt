1. WHAT IS CYPHEX?
================================================================================

Cyphex is an offline-first, autonomous AI-powered cybersecurity platform that
operates entirely from the command line. Given a GitHub repo URL or a local
folder path, Cyphex autonomously:

  1. Scans the source code for vulnerabilities (SAST)
  2. Deploys the app inside a Docker sandbox
  3. Launches 14+ specialized AI attack agents against the live app (DAST)
  4. Has multiple LLM models debate each finding to eliminate false positives
  5. Trains a self-evolving behavioral immune system (Isolation Forest ML)
  6. Auto-generates, reviews, and applies verified code patches

The core design principle: 100% offline. No API keys. No cloud. Your source
code never leaves your machine. Everything runs via local Ollama models.

Target audience: Developers and security engineers who want autonomous security
testing without depending on cloud tools like Snyk, SonarCloud, or Burp Suite.


================================================================================
2. THE PROBLEM IT SOLVES
================================================================================

Modern developers ship fast with AI assistance ("vibe coding") but security
is an afterthought. Existing tools have critical gaps:

  - SAST tools find code patterns but miss runtime vulnerabilities
  - DAST tools test running apps but don't understand source code
  - Neither tool can FIX what they find — only produce noisy reports
  - Cloud-based tools upload your code to third-party servers (a security risk)
  - No existing tool adapts or learns — same rules every run

Cyphex addresses all five gaps in a single CLI command.

3. HOW IT WORKS — THE 8-STEP SCAN PIPELINE
================================================================================

Every `cyphex scan` command executes this fully autonomous pipeline:

  STEP 1 — SOURCE ACQUISITION
    Clone a GitHub repo OR copy a local directory into a working sandbox.

  STEP 2 — STATIC ANALYSIS (SAST)
    Two-layer scan:
    a) Semgrep with 5,000+ community rules (run via WSL on Windows)
    b) Built-in custom regex scanner covering 20+ languages
    Detects: SQLi, XSS, hardcoded secrets, insecure configs, path traversal,
    command injection, SSRF, IDOR, JWT issues, and more.

  STEP 3 — SANDBOX DEPLOYMENT
    Auto-detects the app framework (Express.js, Flask, Django, Docker Compose,
    static HTML) and deploys it in an isolated Docker container or native
    Node.js process. The app runs live so DAST agents can attack it safely.

  STEP 4 — DYNAMIC VULNERABILITY SCAN (DAST)
    14 specialized AI attack agents hit the running application:
      Agent 01 — Recon (fingerprint headers, tech stack)
      Agent 02 — Crawler (discover pages, forms, API routes)
      Agent 02b — API Discovery (SPA route enumeration)
      Agent 03 — SQLi (Union, Boolean, Time-based, Error-based, Stacked)
      Agent 04 — XSS (Reflected, DOM, Event handlers, WAF bypass)
      Agent 05 — Auth (weak credentials, session fixation, token analysis)
      Agent 06 — CMDi (OS command injection, encoding bypass)
      Agent 07 — LFI (path traversal, null byte, directory traversal)
      Agent 08 — Logic (insecure CORS, parameter tampering, authz gaps)
      Agent 09 — IDOR (sequential ID enumeration, UUID prediction)
      Agent 10 — SSRF (internal service probing, cloud metadata access)
      Agent 11 — Supply Chain (NPM/Pip CVE audit, manifest analysis)
      Agent 12 — Prompt Injection (AI endpoint testing)
      Agent 15 — Network (port scanning, service fingerprinting)
    + AI Fuzzer agent for adaptive payload generation
    + Nuclei scanner (8,000+ templates) for template-based DAST

  STEP 5 — AI VERDICT COUNCIL (False Positive Elimination)
    Multiple local LLMs (Qwen, Llama, DeepSeek, Phi) independently review
    each finding. Each model votes CONFIRM or REJECT with a confidence score
    and reasoning chain. Consensus is required — no single model hallucination
    can pass a vulnerability. Built-in anti-hallucination rules enforced.

  STEP 6 — BEHAVIORAL GENOME EVOLUTION (Immune System)
    Red Team vs Blue Team adversarial co-evolution runs over N generations:
      Red Team  → generates & mutates attack payloads
      Blue Team → trains Isolation Forest ML on request feature vectors
      Each generation: blocked payloads trigger mutation; bypassed payloads
      trigger retraining. Block rate climbs from ~60% → 95%+ → 99%+.
    The genome uses a 15-dimensional feature vector per HTTP request:
      [input_length, entropy, special_char_ratio, url_encoding_ratio,
       uppercase_ratio, digit_ratio, max_token_length, keyword_score,
       sqli_pattern_score, null_byte, traversal_depth, bracket_imbalance,
       unicode_ratio, repetition_ratio, token_count]

  STEP 7 — SECURITY REPORT
    Generates a score (0–100), confirmed vulnerability list with CWE mapping,
    severity levels (Critical/High/Medium/Low), and remediation guidance.

  STEP 8 — AUTO-PATCHING + VERIFICATION
    Oracle Reasoning selects the right cognitive strategy → Vectorless RAG
    provides full code context → LLM generates a fix → Council reviews the
    patch → Verification gate checks syntax + blast radius + re-scans the
    vuln → Patch is applied and confirmed. Anti-suppression rules reject
    patches that just add `nosemgrep`, `# noqa`, or `eslint-disable`.

4. KEY INNOVATIONS
================================================================================

4a. ORACLE REASONING ENGINE — Making Small Models Think Like GPT-4
--------------------------------------------------------------------
Small local LLMs (3B–8B params) hallucinate and produce vague patches.
Oracle wraps every LLM call in a cognitive architecture that forces structured,
multi-step reasoning. 16 cognitive strategies, auto-selected by task type:

  Strategy              | When Used
  ----------------------|------------------------------------------
  Chain-of-Thought      | SQLi, XSS patches (CWE-89, CWE-79)
  Self-Reflection       | High severity vulns (draft→critique→improve)
  Tree of Thoughts      | CMDi, SSRF (explores multiple fix branches)
  Self-Consistency      | Critical severity (majority vote from K runs)
  Adversarial Debate    | Council patch review ("why would this fail?")
  Decomposition         | Auth bypass, IDOR (breaks fix into sub-tasks)
  Least-to-Most         | Path traversal (simple cases first, then complex)
  Refinement Loop       | Iterative code improvement (4 rounds)
  Complex Pipeline      | 5-stage: accuracy→structure→depth→examples→polish
  Monte Carlo Search    | MCTS with UCB1 scoring across candidate fixes
  Analogical            | Reasons from known CWE fix patterns by analogy
  Socratic              | Guided questioning to find the root cause
  ReAct                 | Reason + Act loop with code context tools
  Recursive             | Self-executing code verification (REPL agent)
  Meta-Reasoning        | Auto-picks the best strategy for each task
  Standard              | Hardcoded secrets, CORS (direct generation)

Auto-selection logic:
  CWE Override     → CWE-78 (CMDi) always gets Tree-of-Thoughts
  Severity Trigger → Critical vulns get Self-Consistency (3× majority vote)
  Task Mapping     → Patch generation → CoT; Patch review → Self-Reflection
  VRAM Guard       → Low VRAM? Only lightweight strategies used

4b. VECTORLESS RAG — Full Code Context Without a GPU or Vector DB
-----------------------------------------------------------------
Traditional RAG needs an embedding model (2–4 GB VRAM) + a vector database.
Cyphex's Vectorless RAG uses CPU-only keyword indexing and regex scoring:

  Traditional RAG:  Code → GPU Embedding → Vector DB → Similarity Search → Context
  Cyphex:           Code → Keyword Index (CPU) → Regex + Scoring → Context
                    Zero VRAM. Zero external DB. < 50ms per query.

How it works:
  1. Code Indexer walks the source tree, building a keyword index of every file:
     - Route patterns (/api/users, /orders/:id)
     - DB usage (db.query, SELECT, mongoose, prisma)
     - Auth patterns (session, jwt, bcrypt, passport)
     - Input handling (req.body, req.query, request.form)
  2. Smart Retrieval uses multi-signal scoring:
     - Route match (strongest) → finds the file serving the vulnerable endpoint
     - CWE-type relevance → SQLi vuln? Prioritize files with DB queries
     - Payload term match → searches for attack-relevant code patterns
     - Direct location match → exact file:line from the scanner
  3. Secure Pattern Discovery finds how the repo already writes safe code:
     CWE-89 → finds existing parameterized queries in the codebase
     CWE-79 → finds existing HTML sanitization calls
     The LLM is told: "Fix it the way this project already does it."
  4. Two-pass API Route Extraction:
     Pass 1: entry files → finds `app.use('/prefix', require('./routes/x'))`
     Pass 2: route files → finds `router.get/post(...)` with correct prefixes

4c. BEHAVIORAL GENOME — The Cyber Immune System
------------------------------------------------
Flagship innovation. Inspired by biological immune systems. Uses adversarial
co-evolution (Red vs Blue) to build a defense model tuned specifically to your
application. Unlike static WAF rules, the genome evolves and adapts.
Based on scikit-learn's Isolation Forest anomaly detection algorithm.

4d. MULTI-MODEL AI VERDICT COUNCIL
------------------------------------
Multiple independent LLMs debate each finding. No single model can confirm a
vulnerability — consensus is required. Models used:
  - deepseek-coder:1.3b (Detector, always-on, ~1.0 GB VRAM)
  - phi3:mini           (Validator, always-on, ~2.2 GB VRAM)
  - llama3.2:1b         (Narrator, phase-swap, ~1.0 GB VRAM)
  - cyphex-patch        (Patch Agent, patch-only, ~4.5 GB VRAM)

9. RUNTIME PROTECTION — RASP DAEMON
================================================================================

Beyond one-shot scanning, Cyphex includes a persistent runtime daemon:

  cyphex watch --port 3004

The RASP (Runtime Application Self-Protection) daemon:
  - Receives real-time attack telemetry from the app's embedded RASP SDK
  - Scores each incoming request against the trained behavioral genome
  - Flags anomalous requests as potential attacks
  - Auto-patches vulnerable source code when attacks are detected in production
  - Integrates with GitHub webhooks for continuous protection on every push

10. GITHUB WEBHOOK INTEGRATION
================================================================================

  cyphex github-hook --port 3005 --secret <webhook_secret>

  - Connect your GitHub repo's webhook to the Cyphex endpoint
  - On every push/PR, Cyphex auto-clones and scans the new code
  - Patches and reports are generated automatically
  - Enables CI/CD-style continuous security testing


================================================================================
11. HARDWARE AWARENESS
================================================================================

Cyphex's hardware.py module detects available GPU VRAM and assigns models
accordingly:

  Low VRAM  (<4 GB)  → lightweight strategies only, smaller models
  Mid VRAM  (4-8 GB) → standard council models
  High VRAM (8+ GB)  → all 16 reasoning strategies, larger models

This ensures Cyphex works on everything from a laptop to a workstation.

12. SECURITY PHILOSOPHY
================================================================================

  - No cloud APIs     — source code, reports, and patches never leave the machine
  - No API keys       — runs entirely on local Ollama models
  - No telemetry      — zero analytics, zero phone-home behavior
  - Offline-first     — works in air-gapped environments and offline labs
  - Open source       — fully auditable; every line that scans your code is readable
  - Anti-suppression  — rejects patches that add nosemgrep / eslint-disable / noqa
